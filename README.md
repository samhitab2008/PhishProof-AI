# PhishProof AI

PhishProof AI is a college hackathon prototype that helps people pause and inspect suspicious emails, texts, and other messages. It highlights evidence such as urgent language, requests for credentials or payment, account threats, and visible URL formatting. It is an aid for learning and triage—not a security service or a verdict.

## The problem

Phishing messages often pressure people to act quickly, share sensitive information, or follow links to unfamiliar websites. A recipient may not know which parts of a message deserve a closer look.

PhishProof provides an investigation report with a risk assessment, evidence-based warning signs, and recommended next steps. Users should verify unexpected requests through a contact method or website they already trust.

## Features in this project

- Accepts message text up to 10,000 characters.
- Uses Google's Gemini API for AI-assisted analysis when configured and available. The current model setting is `gemini-3.8-flash`.
- Presents High, Medium, or Low Risk, an explanation, warning signs, recommended actions, and a final summary.
- Checks up to eight visible URLs for formatting characteristics. Checks include plain HTTP, IP-address hosts, punycode, nested subdomains, brand-like terms in subdomains, known link shorteners, non-standard ports, and unusually long URLs.
- Explains that URL observations are not a reputation lookup and do not prove that a URL is malicious.
- Uses a clearly labelled **“Basic rule-based analysis — Gemini unavailable”** report for supported provider outages, quota/rate-limit failures, and timeouts. The local rules inspect wording and visible URL formatting; they are not Gemini analysis.
- Keeps up to ten recent checks in browser `localStorage`. Stored history contains dates, risk levels, and aggregate counts, not the submitted message or its URLs.
- Provides input validation, request timeouts, safe JSON errors, and a responsive HTML/CSS interface.

### How fallback differs from Gemini

Gemini analysis is generated remotely when the server has a configured API key and the provider request succeeds. The report identifies this source as **“Gemini AI analysis.”**

For quota/rate-limit errors, Gemini timeouts, network failures, and Gemini 5xx errors, the server returns the local rule-based report with the fallback label. It does not pretend this report was generated by Gemini. Invalid credentials, permission/model errors, malformed AI output, and other unclassified failures may instead return an error response; they are not represented as successful AI analysis.

The fallback recognizes patterns such as urgency or short deadlines, credential/account verification requests, account-suspension threats, payment requests, and flagged URL formatting. A combination of severe warning categories can produce High Risk. A message that matches none of these patterns can still be unsafe.

## Technology

- **Frontend:** HTML, CSS, and browser JavaScript; served by Express.
- **Backend:** Node.js and Express.
- **AI integration:** Google's `@google/genai` SDK, with `dotenv` loading the server-side `.env` file.
- **Tests:** Node.js built-in test runner (`node:test`) with mocked Gemini responses and failures. Tests do not make live Gemini requests.

## Requirements

- Windows with PowerShell and [Node.js](https://nodejs.org/) installed.
- VS Code (recommended).
- A Gemini API key is needed for live Gemini analysis. The rule-based fallback can still produce reports during supported provider outages after the app has been configured.

## Setup and run on Windows

1. Open the project folder in VS Code.
2. Open **Terminal → New Terminal** and confirm the terminal is in the project directory (the folder containing `package.json`).
3. Install dependencies:

   ```powershell
   npm.cmd install
   ```

4. Create a file named `.env` in the project root, beside `server.js`. Add your key locally:

   ```dotenv
   GEMINI_API_KEY=PASTE_YOUR_GEMINI_API_KEY_HERE
   ```

   Replace the placeholder in your local file with your own key. Do not paste the key into chat, frontend code, screenshots, or source control. The project `.gitignore` excludes `.env`.

5. Start the server:

   ```powershell
   node server.js
   ```

6. Open [http://localhost:3000](http://localhost:3000) in your browser. Leave the terminal running while you use the website.

To stop the server, focus its terminal and press **Ctrl+C**. If port 3000 is already in use, stop the other local server or set a different `PORT` value in the environment before starting this one.

## Run the tests

In PowerShell, run:

```powershell
npm.cmd test
```

The suite covers the health endpoint, invalid inputs, response shape, Gemini success and failure paths, rule-based fallback behavior, timeout handling, and safe logging. Gemini is mocked in tests; passing tests do **not** confirm live API access, model availability, or quota.

## Demo walkthrough

1. Start the app and open `http://localhost:3000`.
2. Submit a fictional suspicious example, such as a message that combines an urgent deadline with an account-verification or payment request.
3. Review the risk level, the evidence and explanation for each warning sign, the URL formatting notes (if present), and the recommendations.
4. Submit a harmless fictional note, such as a plan to meet at the library. Review the result as an assessment of visible signs—not proof that the message is safe.
5. When Gemini is available, the report identifies **Gemini AI analysis**. During supported provider quota or availability failures, the site instead labels the result **Basic rule-based analysis — Gemini unavailable**.
6. Show the recent-check list to demonstrate local history. It stores summary counts and risk levels rather than message text or URLs.

Use fictional content for demonstrations. Avoid submitting real credentials, one-time codes, personal information, or private messages.

## Limitations and safety

- Risk classifications can be wrong. Phishing can be subtle, and the local fallback only recognizes a limited set of patterns.
- The project does not visit links or query a threat-intelligence/reputation service. A formatting warning is not proof that a URL is malicious; the absence of a warning is not proof that it is safe.
- A Low Risk result is not a guarantee. Do not rely on this tool alone for security decisions.
- Confirm unexpected requests independently. Do not share passwords, one-time codes, or payment details in response to unsolicited messages.
- Live Gemini use depends on API key validity, network access, model availability, and the account's usage limits. This repository's automated tests do not verify those live conditions.

## Possible future improvements

- Improve evaluation and calibration using labeled examples, while keeping uncertainty visible.
